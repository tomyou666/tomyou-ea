# MT4–Python インターフェース設計書

本ドキュメントは、MT4（MQL4 EA）と Python サーバー間で ZeroMQ を用いてやり取りする**データ形式**を定義する。

---

## 1. 通信概要

| 項目 | 内容 |
|------|------|
| プロトコル | ZeroMQ（PUSH/PULL） |
| MT4 → Python | **PUSH**（MT4が送信）/ **PULL**（Pythonが受信） |
| Python → MT4 | **PUSH**（Pythonが送信）/ **PULL**（MT4が受信） |
| デフォルトポート | 受信（MT4→Python）: **5555** / 送信（Python→MT4）: **5556** |
| メッセージ単位 | 1 メッセージ = 1 件（ティック 1 行 or JSON 1 件） |

- MT4 は PUSH でティック・注文結果を送り、PULL で注文コマンドを受信する。
- Python は PULL でティック・注文結果を受け取り、PUSH で注文コマンドを送る。

---

## 2. MT4 → Python（MT4 が送信）

### 2.1 ティックデータ（CSV）

**用途**: リアルタイム価格の配信。MT4 が `SendIntervalMs` 間隔で PUSH 送信する。

| 項目 | 内容 |
|------|------|
| 形式 | CSV（カンマ区切り、1 行 = 1 ティック） |
| 文字コード | 実装依存（Python 側は UTF-8 想定で受信） |
| 区切り | カンマ `,`（フィールド前後のスペースは許容） |

**フィールド順（5 列）**:

| 列 | 名前 | 型 | 説明 |
|----|------|-----|------|
| 1 | symbol | 文字列 | 通貨ペア（例: `USDJPY`） |
| 2 | bid | 小数 | 売値（Bid） |
| 3 | ask | 小数 | 買値（Ask） |
| 4 | spread | 整数 | スプレッド（ポイント） |
| 5 | time | 文字列 | 日時 `YYYY.MM.DD HH:MM:SS` |

**例**:

```
USDJPY, 149.123, 149.125, 2, 2025.01.29 12:00:00
```

**Python 側**: `TickProcessor` / `ProcessorUtil.parse_line()` で 1 行を `TickDto` に変換。日時は `%Y.%m.%d %H:%M:%S` でパースし、失敗時は文字列のまま保持する。

---

### 2.2 注文結果（JSON）

**用途**: 新規注文・決済の成否を Python に通知する。MT4 が `OrderSend` / `OrderClose` 実行後に PUSH で送信する。MT4 は対応するリクエスト（ORDER / CLOSE）の **request_id** をそのまま応答の request_id に設定して返す。

| 項目 | 内容 |
|------|------|
| 形式 | JSON オブジェクト（1 メッセージ = 1 件） |
| 送信タイミング | 注文成功時・失敗時・決済成功時・決済失敗時 |

---

**成功時フィールド**:

| キー | 型 | 必須 | 説明 |
|------|-----|------|------|
| type | 文字列 | ○ | `"order_result"`（メッセージ種別） |
| request_id | 文字列 | ○ | 対応するリクエストの request_id（Python が送った値をそのまま返す） |
| ticket | 整数 | ○ | チケット番号 |
| status | 文字列 | ○ | `"SUCCESS"` |

**成功時の例**:

```json
{"type":"order_result","request_id":"req-ord-001","ticket":12345,"status":"SUCCESS"}
```

---

#### 失敗した場合

下記の形式でデータレスポンスを返す。

**失敗時フィールド**:

| キー | 型 | 必須 | 説明 |
|------|-----|------|------|
| request_id | 文字列 | △ | リクエストID（ある場合のみ含める） |
| status | 文字列 | ○ | `"FAILED"` |
| code | 整数 | ○ | エラーコード番号（[6. エラーコード一覧](#6-エラーコード一覧)を参照） |
| message | 文字列 | ○ | 失敗原因 |

**失敗時の例**:

```json
{"request_id":"req-ord-001","status":"FAILED","code":138,"message":"Requote（価格変動）"}
```

```json
{"request_id":"req-close-001","status":"FAILED","code":1,"message":"指定チケットが存在しません"}
```

### 2.3 価格情報応答（JSON）

**用途**: PriceInfo 命令に対する応答。MT4 が指定シンボルのポイント・桁数・ピップスを PUSH で返す。

| 項目 | 内容 |
|------|------|
| 形式 | JSON オブジェクト（1 メッセージ = 1 件） |
| 送信タイミング | Python から `action: "PRICE_INFO"` を受信した直後。MT4 はリクエストの **request_id** をそのまま応答の request_id に設定して返す。 |

応答は**成功時**と**失敗時**でデータ形式が異なる。

#### 成功した場合

| キー | 型 | 必須 | 説明 |
|------|-----|------|------|
| type | 文字列 | ○ | `"price_info"`（メッセージ種別） |
| request_id | 文字列 | ○ | 対応するリクエストの request_id（Python が送った値をそのまま返す） |
| status | 文字列 | ○ | `"SUCCESS"` |
| symbol | 文字列 | ○ | 対象通貨ペア |
| point | 小数 | ○ | 最小価格変動（MT4 の `MODE_POINT`） |
| digits | 整数 | ○ | 価格の小数点桁数（MT4 の `MODE_DIGITS`） |
| pips | 小数 | ○ | 1 ピップスあたりの価格（5 桁ブローカーでは通常 `point * 10`、4 桁では `point`） |

**例**:

```json
{"type":"price_info","request_id":"req-001","status":"SUCCESS","symbol":"USDJPY","point":0.001,"digits":3,"pips":0.01}
```

#### 失敗した場合

シンボルが無効・マーケット情報を取得できない場合などは、注文結果と同様の失敗時形式で返す。

| キー | 型 | 必須 | 説明 |
|------|-----|------|------|
| request_id | 文字列 | △ | リクエストID（ある場合のみ含める） |
| status | 文字列 | ○ | `"FAILED"` |
| code | 整数 | ○ | エラーコード番号（[6. エラーコード一覧](#6-エラーコード一覧)を参照） |
| message | 文字列 | ○ | 失敗原因（人間が読める説明） |

**例**:

```json
{"request_id":"req-001","status":"FAILED","code":10,"message":"シンボルが無効です（価格情報を取得できません）"}
```

**Python 側**: `type == "price_info"` の場合は成功応答として `PriceInfo` を扱う。`status == "FAILED"` かつ `code` / `message` を持つ場合は失敗応答として扱う。

### 2.4 注文情報応答（JSON）

**用途**: OrderInfo 命令に対する応答。チケット指定・引数なしのいずれの場合も、**同一の応答形式**（`type: "order_info_list"`, `count`, `orders`）で返す。

| 項目 | 内容 |
|------|------|
| 形式 | JSON オブジェクト（1 メッセージ = 1 件） |
| 送信タイミング | Python から `action: "ORDER_INFO"` を受信した直後。MT4 はリクエストの **request_id** をそのまま応答の request_id に設定して返す。 |

応答は**成功時**と**失敗時**でデータ形式が異なる。チケット指定で該当注文が無い場合は**成功**（`count: 0`, `orders: []`）とする。リクエストの処理そのものが失敗した場合のみ失敗時形式を返す。

#### 成功した場合

**共通フィールド**:

| キー | 型 | 必須 | 説明 |
|------|-----|------|------|
| type | 文字列 | ○ | `"order_info_list"`（メッセージ種別） |
| request_id | 文字列 | ○ | 対応するリクエストの request_id（Python が送った値をそのまま返す） |
| status | 文字列 | ○ | `"SUCCESS"` |
| count | 整数 | ○ | 注文件数（0 以上） |
| orders | 配列 | ○ | 注文オブジェクトの配列。0 件の場合は空配列 `[]` |

**orders 配列の各要素（1 注文あたり）**:

| キー | 型 | 必須 | 説明 |
|------|-----|------|------|
| ticket | 整数 | ○ | チケット番号 |
| status | 文字列 | ○ | 取得結果。`"OK"` = 取得成功 |
| symbol | 文字列 | ○ | 通貨ペア |
| order_type | 文字列 | ○ | 注文種別: `"BUY"` / `"SELL"` / `"BUY_LIMIT"` / `"SELL_LIMIT"` / `"BUY_STOP"` / `"SELL_STOP"` |
| lots | 小数 | ○ | ロット数 |
| open_price | 小数 | ○ | 約定価格（未約定の指値・逆指値の場合は発動価格） |
| sl | 小数 | △ | ストップロス価格。未設定時は 0 |
| tp | 小数 | △ | テイクプロフィット価格。未設定時は 0 |
| open_time | 文字列 | △ | オープン日時 `YYYY.MM.DD HH:MM:SS`。未約定の場合は空文字または省略可 |
| close_time | 文字列 | △ | クローズ日時。未決済の場合は空文字または省略可 |
| profit | 小数 | △ | 現在損益（ポジションの場合）。未約定・既決済の場合は 0 または省略可 |

- **チケット指定で該当あり**: `count: 1`, `orders: [ 上記1件 ]`。
- **チケット指定で該当なし（TICKET_NOT_FOUND / INVALID_TICKET）**: `count: 0`, `orders: []`。
- **引数なし（全注文）**: `count: N`, `orders: [ 上記 N 件 ]`。EA が扱う注文のみ（同一 MagicNumber 等）を含む。

**例（チケット指定・1 件取得成功）**:

```json
{"type":"order_info_list","request_id":"req-002","status":"SUCCESS","count":1,"orders":[{"ticket":12345,"status":"OK","symbol":"USDJPY","order_type":"BUY","lots":0.01,"open_price":149.12,"sl":148.50,"tp":150.00,"open_time":"2025.01.29 10:00:00","close_time":"","profit":-0.5}]}
```

**例（チケット指定・該当なし）**:

```json
{"type":"order_info_list","request_id":"req-002","status":"SUCCESS","count":0,"orders":[]}
```

**例（引数なし・2 件）**:

```json
{"type":"order_info_list","request_id":"req-002","status":"SUCCESS","count":2,"orders":[{"ticket":12345,"status":"OK","symbol":"USDJPY","order_type":"BUY","lots":0.01,"open_price":149.12,"sl":148.50,"tp":150.00,"open_time":"2025.01.29 10:00:00","close_time":"","profit":-0.5},{"ticket":12346,"status":"OK","symbol":"USDJPY","order_type":"SELL_LIMIT","lots":0.01,"open_price":150.00,"sl":0,"tp":0,"open_time":"","close_time":"","profit":0}]}
```

**例（引数なし・0 件）**:

```json
{"type":"order_info_list","request_id":"req-002","status":"SUCCESS","count":0,"orders":[]}
```

#### 失敗した場合

注文情報の取得処理そのものが失敗した場合（内部エラー等）は、注文結果と同様の失敗時形式で返す。

| キー | 型 | 必須 | 説明 |
|------|-----|------|------|
| request_id | 文字列 | △ | リクエストID（ある場合のみ含める） |
| status | 文字列 | ○ | `"FAILED"` |
| code | 整数 | ○ | エラーコード番号（[6. エラーコード一覧](#6-エラーコード一覧)を参照） |
| message | 文字列 | ○ | 失敗原因（人間が読める説明） |

**例**:

```json
{"request_id":"req-002","status":"FAILED","code":11,"message":"注文情報の取得に失敗しました"}
```

**Python 側**: `type == "order_info_list"` の場合は成功応答として `OrderInfoList` を扱う。`status == "FAILED"` かつ `code` / `message` を持つ場合は失敗応答として扱う。

### 2.5 ペンディング約定通知（JSON）

**用途**: 指値（BUY_LIMIT / SELL_LIMIT）・逆指値（BUY_STOP / SELL_STOP）のペンディング注文が価格到達により約定し、ポジションがオープンした際に、MT4 が Python へ**リアルタイム**で通知する。

| 項目 | 内容 |
|------|------|
| 形式 | JSON オブジェクト（1 メッセージ = 1 件） |
| 送信タイミング | ペンディング注文が約定してポジションに変わった直後（MT4 の `OnTick` 内で検知し、同一 PUSH ソケットで送信） |

**フィールド**:

| キー | 型 | 必須 | 説明 |
|------|-----|------|------|
| type | 文字列 | ○ | `"pending_opened"`（メッセージ種別） |
| ticket | 整数 | ○ | 約定したポジションのチケット番号（MT4 ではペンディング約定後も同一チケットが流用される場合がある） |
| symbol | 文字列 | ○ | 通貨ペア |
| order_type | 文字列 | ○ | 元の注文種別: `"BUY_LIMIT"` / `"SELL_LIMIT"` / `"BUY_STOP"` / `"SELL_STOP"` |
| lots | 小数 | ○ | ロット数 |
| open_price | 小数 | ○ | 約定価格 |
| open_time | 文字列 | ○ | 約定日時 `YYYY.MM.DD HH:MM:SS` |

**例**:

```json
{"type":"pending_opened","ticket":12346,"symbol":"USDJPY","order_type":"BUY_LIMIT","lots":0.01,"open_price":148.50,"open_time":"2025.01.29 14:30:00"}

## 3. Python → MT4（Python が送信）

### 3.0 応答待ち・タイムアウト・リトライとリクエストID

Python が MT4 へコマンドを送信し、**応答を待つ**場合（PRICE_INFO・ORDER_INFO 等）の挙動を以下で定義する。

| 項目 | 内容 |
|------|------|
| 応答待ち最大時間（タイムアウト） | 1 回あたりの応答を待つ最大時間。**デフォルト: 3 秒**。設定可能とする。 |
| リトライ回数 | タイムアウトまたは検証失敗時、同一リクエストを再送する回数。**最大 3 回**（初回含めて合計 3 回送信）。 |
| リクエストID | リクエスト JSON に **request_id**（一意の識別子）を含める。MT4 は応答 JSON に同じ **request_id** をそのまま含めて返す。Python は受信した応答の request_id が送信したリクエストの request_id と一致することを検証する。一致しない応答は無視し、タイムアウト扱いとする。 |
| 失敗時の扱い | 3 回すべてタイムアウトまたは検証失敗した場合、**エラー**とする。呼び出し元にエラーを返すか例外で通知する。 |

- リクエストID は、複数リクエストが飛んでいる場合に「どのリクエストに対する応答か」を一意に判定するために必須とする。
- タイムアウトまたは request_id 不一致の応答を受信した場合は、その回を失敗とみなし、リトライ可能なら再送する。

---

### 3.1 注文コマンド（JSON）

**用途**: 新規注文または決済を MT4 に指示する。Python の命令部が PUSH で送信する。

| 項目 | 内容 |
|------|------|
| 形式 | JSON オブジェクト（1 メッセージ = 1 コマンド） |
| 共通キー | `action` で ORDER / CLOSE を判別。応答を待つコマンド（ORDER / CLOSE / PRICE_INFO / ORDER_INFO）では **request_id** を必須とする。 |

---

#### 3.1.1 新規注文（action = "ORDER"）

**注文種別（成行・指値・逆指値）**:

| type の値 | 意味 | price の扱い |
|-----------|------|----------------|
| BUY | 成行買い | 0（現在の Ask で約定） |
| SELL | 成行売り | 0（現在の Bid で約定） |
| BUY_LIMIT | 指値買い | 必須。この価格以下で買い注文を出す |
| SELL_LIMIT | 指値売り | 必須。この価格以上で売り注文を出す |
| BUY_STOP | 逆指値買い | 必須。この価格以上で買い注文を出す |
| SELL_STOP | 逆指値売り | 必須。この価格以下で売り注文を出す |

- **成行**: 即時約定を想定。MT4 側で現在価格を用いて `OrderSend` する。
- **指値（Limit）**: 指定価格より有利な方向に価格が到達したら約定。BUY_LIMIT は現価より安い価格、SELL_LIMIT は現価より高い価格を指定する。
- **逆指値（Stop）**: 指定価格に到達したら成行として約定。BUY_STOP は現価より高い価格、SELL_STOP は現価より安い価格を指定する。

**フィールド**:

| キー | 型 | 必須 | 説明 |
|------|-----|------|------|
| action | 文字列 | ○ | `"ORDER"` |
| request_id | 文字列 | ○ | 一意のリクエストID。応答（order_result）の検証に使用 |
| symbol | 文字列 | △ | 通貨ペア。省略時は MT4 の `Symbol()` を使用 |
| type | 文字列 | ○ | 注文種別: `"BUY"` / `"SELL"`（成行）、`"BUY_LIMIT"` / `"SELL_LIMIT"`（指値）、`"BUY_STOP"` / `"SELL_STOP"`（逆指値） |
| lots | 小数 | △ | ロット数。省略時は 0.01 等のデフォルト |
| sl | 小数 | △ | ストップロス価格。0 は未指定 |
| tp | 小数 | △ | テイクプロフィット価格。0 は未指定 |
| price | 小数 | △ | 成行の場合は 0（MT4 側で現在価格を使用）。指値・逆指値の場合は**発動価格**（必須） |

**例（成行）**:

```json
{"action":"ORDER","request_id":"req-ord-001","symbol":"USDJPY","type":"BUY","lots":0.01,"sl":0,"tp":0}
```

**例（指値買い）**:

```json
{"action":"ORDER","request_id":"req-ord-002","symbol":"USDJPY","type":"BUY_LIMIT","lots":0.01,"price":148.50,"sl":148.00,"tp":149.50}
```

**例（逆指値売り）**:

```json
{"action":"ORDER","request_id":"req-ord-003","symbol":"USDJPY","type":"SELL_STOP","lots":0.01,"price":148.00,"sl":148.50,"tp":147.50}
```

#### 3.1.2 決済（action = "CLOSE"）

**フィールド**:

| キー | 型 | 必須 | 説明 |
|------|-----|------|------|
| action | 文字列 | ○ | `"CLOSE"` |
| request_id | 文字列 | ○ | 一意のリクエストID。応答（order_result）の検証に使用 |
| ticket | 整数 | ○ | 決済するポジションのチケット番号 |

**例**:

```json
{"action":"CLOSE","request_id":"req-close-001","ticket":12345}
```

#### 3.1.3 価格情報取得（action = "PRICE_INFO"）

**用途**: 指定シンボルのポイント・桁数・ピップスを MT4 に問い合わせる。MT4 は同一 PUSH ソケットで `type: "price_info"` の JSON を返す。

**フィールド**:

| キー | 型 | 必須 | 説明 |
|------|-----|------|------|
| action | 文字列 | ○ | `"PRICE_INFO"` |
| request_id | 文字列 | ○ | 一意のリクエストID。応答（price_info）の検証に使用 |
| symbol | 文字列 | △ | 通貨ペア。省略時は MT4 の `Symbol()` を使用 |

**例**:

```json
{"action":"PRICE_INFO","request_id":"req-001","symbol":"USDJPY"}
```

#### 3.1.4 注文情報取得（action = "ORDER_INFO"）

**用途**: 注文・ポジション情報を MT4 に問い合わせる。チケット指定時は最大 1 件、引数なし時は EA が扱う全注文を返す。MT4 は常に同一 PUSH ソケットで `type: "order_info_list"`（count, orders）の JSON を返す。

**フィールド**:

| キー | 型 | 必須 | 説明 |
|------|-----|------|------|
| action | 文字列 | ○ | `"ORDER_INFO"` |
| request_id | 文字列 | ○ | 一意のリクエストID。応答（order_info_list）の検証に使用 |
| ticket | 整数 | △ | 照会する注文・ポジションのチケット番号。**省略時は EA が扱うすべての注文**を返す（2.4.2 の形式で応答） |

**例（1 件指定）**:

```json
{"action":"ORDER_INFO","request_id":"req-002","ticket":12345}
```

**例（全注文）**:

```json
{"action":"ORDER_INFO","request_id":"req-002"}
```

## 4. データ型対応表（Python DTO）

| 通信方向 | メッセージ種別 | Python モデル（dto.py） | 備考 |
|----------|----------------|--------------------------|------|
| MT4→Python | ティック CSV | `TickDto` | symbol, bid, ask, spread, time |
| MT4→Python | 注文結果 JSON（成功） | `OrderResult` | type, request_id, ticket, status（SUCCESS） |
| MT4→Python | 注文結果 JSON（失敗） | エラー応答 | request_id?, status（FAILED）, code, message（[6. エラーコード一覧](#6-エラーコード一覧)参照） |
| MT4→Python | 価格情報 JSON（成功） | `PriceInfo` | type, request_id, status（SUCCESS）, symbol, point, digits, pips |
| MT4→Python | 価格情報 JSON（失敗） | エラー応答 | request_id?, status（FAILED）, code, message（[6. エラーコード一覧](#6-エラーコード一覧)参照） |
| MT4→Python | 注文情報応答 JSON（成功） | `OrderInfoList`（count, orders: List[OrderInfo]） | type: order_info_list, request_id, status（SUCCESS）, count, orders。チケット指定・引数なしで同一形式 |
| MT4→Python | 注文情報応答 JSON（失敗） | エラー応答 | request_id?, status（FAILED）, code, message（[6. エラーコード一覧](#6-エラーコード一覧)参照） |
| MT4→Python | ペンディング約定通知 JSON | `PendingOpened` | type, ticket, symbol, order_type, lots, open_price, open_time |
| Python→MT4 | 注文コマンド JSON | `OrderCommand` | action, request_id, symbol, type（成行/指値/逆指値）, lots, sl, tp, price, ticket 等 |
| Python→MT4 | 価格情報取得 JSON | 命令オブジェクト | action: PRICE_INFO, request_id, symbol |
| Python→MT4 | 注文情報取得 JSON | 命令オブジェクト | action: ORDER_INFO, request_id。ticket 省略時は全注文取得 |

## 5. エラー・境界条件

- **Python → MT4 応答待ち**: タイムアウト（デフォルト 3 秒）以内に応答が得られない場合、または受信した応答の **request_id** が送信したリクエストの request_id と一致しない場合は、その回を失敗とする。最大 3 回までリトライし、**3 回すべて失敗した場合はエラー**とする。呼び出し元にエラーを返すか例外で通知する。
- **ティック CSV**: 列数が 5 未満、または数値/日時パース失敗時は Python 側で `None` を返し、ログに警告を出す。
- **注文結果**: 成功時は `type`, `request_id`, `ticket`, `status: "SUCCESS"` の形式。失敗時は 2.2 の失敗時形式（`request_id`（ある場合）, `status: "FAILED"`, `code`, `message`）で返す。Python 側は `status` が `"FAILED"` のときは `code` と `message` で失敗原因を判定する。
- **ペンディング約定通知**: 指値・逆指値のみが対象。成行注文の約定は従来どおり `order_result` の `SUCCESS` で通知する。同一チケットがペンディングからポジションに変わるため、Python 側でチケット管理する場合は「ペンディング登録済みチケットがオープンした」として扱う。
- **価格情報応答**: 成功時は `type == "price_info"` で `status: "SUCCESS"`, symbol, point, digits, pips を含む。失敗時は 2.3 の失敗時形式（`request_id`（ある場合）, `status: "FAILED"`, `code`, `message`）で返す。
- **注文情報応答**: 成功時は `type == "order_info_list"` で `status: "SUCCESS"`, `count`, `orders` を含む。チケット指定で該当なしの場合は `count: 0`, `orders: []`（成功扱い）。失敗時は 2.4 の失敗時形式（`request_id`（ある場合）, `status: "FAILED"`, `code`, `message`）で返す。`orders` 内の各要素は status が `"OK"` のときのみ注文詳細を持つ。EA の「扱う注文」は MagicNumber や実装で定義する。
- **注文コマンド**: MT4 側で JSON デシリアライズ失敗時は「不明なコマンド」としてログ出力し、`action` が空または未知の場合は同様に扱う。指値・逆指値（`BUY_LIMIT` / `SELL_LIMIT` / `BUY_STOP` / `SELL_STOP`）の場合は `price` が必須であり、0 または未指定の場合は注文失敗として扱う。
- **リトライ**: MT4 側は注文実行時にリトライ可能エラー（Requote、価格変動、タイムアウト等）で `OrderRetryCount`・`OrderRetryDelayMs` に従い再試行する。インターフェースのデータ形式はリトライの有無に依存しない。

| code | 定数名 | message（説明） |
|------|--------|------------------|
| 1 | TICKET_NOT_FOUND | 指定チケットが存在しません |

| 11 | ORDER_INFO_FAILED | 注文情報の取得に失敗しました |

|------|----------------------|
| 64 | アカウントが無効 |
| 65 | 無効なトレード口座 |

| 129 | 無効な価格 |
| 134 | 証拠金不足 |
| 135 | 価格変動 |
| 136 | オフクォート |
| 138 | Requote（価格変動） |
